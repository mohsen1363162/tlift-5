## محیط و مرز ایزوله‌سازی

هر سناریو در context مرورگر تازه و با قرارداد، مدیر، قطعه، عکس و گزارش ساختگی اجرا می‌شود. درخواست‌های PHP توسط Playwright پاسخ داده می‌شوند؛ سایر درخواست‌های خارجی و WebSocketها مسدودند. داده bootstrap واقعی بارگذاری نمی‌شود. سوپابیس در Build آزمایشی غیرفعال است. مسیر PHP شبیه‌سازی‌شده از همان کد واقعی cloudSync استفاده می‌کند، نه پیاده‌سازی جایگزین منطق صف.

Build جداگانه `tests/harness` کد واقعی برنامه و APIهای store/sync/backup را وارد می‌کند. این دسترسی‌ها فقط در harness وجود دارند؛ entry اصلی src/main.tsx هیچ hook آزمایشی ندارد. harness خارج از context ایزوله قبل از import برنامه متوقف می‌شود و داخل dist/ZIP انتشار قرار نمی‌گیرد.

ثبت سرویس و تخصیص آن از رابط موبایل انجام می‌شود؛ کنترل دقیق قطع/وصل، تزریق خطا و فراخوانی توابع backup/sync از API همان ماژول‌های واقعی در harness انجام می‌شود. دانلود فایل JSON نیز با رویداد download مرورگر بررسی می‌شود.

## ایرادهای بازتولیدشده و اصلاحات

1. راه‌اندازی قبلی بر اساس نشان bootstrap و نبود meta، صف گزارش را بدون تأیید سرور حذف می‌کرد. این حذف خودکار کنار گذاشته شد.
2. پاسخ موفق قدیمی، ویرایش جدید را حذف می‌کرد و پاسخ ناموفق قدیمی، آن را با داده قدیمی جایگزین می‌کرد. اکنون برای هر کلید یک ارسال فعال و snapshot مستقل وجود دارد؛ فقط همان snapshot تأییدشده از صف خارج می‌شود.
3. هر پاسخ 200 ذخیره موفق فرض می‌شد. اکنون پاسخ JSON با `ok: true` و شماره کلید سازگار لازم است؛ HTML/خطا باعث حفظ صف می‌شود. ارسال جزئی نیز موفقیت کامل اعلام نمی‌شود.
4. بازیابی رشته خام مثل نام دستگاه، علامت نقل‌قول اضافه می‌کرد. داده خام اختیاری `rawEntries` در قالب نسخه ۱ اضافه شده است؛ خواننده جدید بک‌آپ‌های قدیمی بدون این فیلد را نیز می‌پذیرد.
5. بازیابی، صف را مثل داده تجاری دوباره داخل صف ارسال قرار می‌داد و نشست/هویت دستگاه را نیز وارد مسیر sync می‌کرد. اکنون صف‌های بک‌آپ و دستگاه ادغام می‌شوند، صف جاری اولویت دارد و هویت/توکن/نشست فعلی دستگاه بازنویسی یا ارسال نمی‌شوند. این مقادیر از خود دستگاه حذف نشده‌اند؛ بک‌آپ‌های قدیمی نیز تغییر نکرده‌اند.
6. قالب نامعتبر entries پذیرفته می‌شد. اعتبارسنجی قالب، rawEntries و ساختارهای اصلی پیش از نوشتن انجام می‌شود؛ خطای نوشتن تست‌شده rollback می‌شود.
7. مسیر JSON و IndexedDB اکنون restore مشترک دارند؛ موفقیت نوشتن IndexedDB پس از complete تراکنش گزارش می‌شود، نه فقط موفقیت request.

## رفتار مهم بازیابی

پس از restore، **حالت آفلاین دستی فعال می‌ماند**. ابتدا اطلاعات را بررسی کنید، سپس همگام‌سازی را روشن کنید. پیام بخش cPanel نیز به همین موضوع اشاره می‌کند. ویرایش‌های ارسال‌نشده فعلی بر مقادیر قدیمی همان کلید در بک‌آپ اولویت دارند؛ لیست پیش‌نویس‌ها و سرویس‌های آفلاین با شناسه ادغام می‌شود. فایل بک‌آپ منبع دست‌نخورده باقی می‌ماند.

نام کلیدهای localStorage و نسخه/schema پایگاه IndexedDB تغییر نکرده است. rawEntries فقط metadata اختیاری در فایل بک‌آپ است و برای نسخه‌های قدیمی بک‌آپ لازم نیست. برای حفظ encoding دقیق بک‌آپ‌های جدید از restore نسخه 3.36.10 یا جدیدتر استفاده کنید.

rollback در خطای هم‌زمان نوشتن آزمایش شده است؛ localStorage تراکنش چندکلیدی واقعی ندارد و این کنترل تضمین قطع برق/بسته‌شدن ناگهانی مرورگر در میانه restore نیست.

## اجرای مجدد

```bash
npm ci
npm run build
python3 scripts/check_release.py
npm run test:recovery:build
npx playwright install --with-deps chromium
```

دو سرور موقت را در ترمینال‌های جدا اجرا کنید:

```bash
npm run preview -- --host 0.0.0.0 --port 4173
npx vite preview --config tests/harness/vite.config.ts
```

سپس:

```bash
npm run test:smoke
npm run test:recovery -- --repeat-each=3
```

در این Session از مرورگر آماده‌شده خارج از Git استفاده شد:

```bash
LD_LIBRARY_PATH=/tmp/al2023/lib CHROMIUM_EXECUTABLE_PATH=/tmp/chromium npm run test:recovery -- --repeat-each=3
LD_LIBRARY_PATH=/tmp/al2023/lib CHROMIUM_EXECUTABLE_PATH=/tmp/chromium npm run test:smoke
```

فایل‌های موقت harness در node_modules/.cache و نتایج مرورگر در test-results هستند و وارد Git نمی‌شوند. آدرس‌های localhost فقط برای runner محلی‌اند و در برنامه کاربران استفاده نشده‌اند.

## محدودیت و تصمیم انتشار

این نتایج صحت سناریوهای بالا را در Chromium با سرور PHP شبیه‌سازی‌شده نشان می‌دهد، نه سلامت هاست واقعی، احراز هویت واقعی، سوپابیس یا همه تعارض‌های چندکاربره. Service Worker برای کنترل شبکه در این آزمون‌ها مسدود است؛ cold-start آفلاین PWA نصب‌شده و Android واقعی هنوز آزموده نشده‌اند. بک‌آپ JSON عکس‌های inline و نشانی عکس‌های خارجی را نگه می‌دارد، اما فایل تصاویر خارجی سرور را داخل JSON بسته‌بندی نمی‌کند.

پیش از انتشار اصلی، آزمون staging مجزا با PHP واقعی و داده ساختگی، آزمون نصب/بازشدن آفلاین PWA روی گوشی و بک‌آپ مستقل از فایل‌ها و داده‌های هاست توصیه می‌شود. ZIP نباید با پاک‌کردن uploads، sync_data، private یا بک‌آپ‌های زنده نصب شود. هیچ APK عمومی اضافه نشده است.
